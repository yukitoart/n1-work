# YouTube「儲けのカラクリ研究所」制作フロー

身近な企業の「儲けのカラクリ」を決算の数字で解き明かす、顔出し・声出しなしの解説チャンネル。
台本・図解・ナレーション・字幕・サムネイル・概要欄までを AI とスクリプトで生成し、
**人間は「切り口の決定」「事実確認」「試写」の3点だけ**を担当する。
（チャンネル名は仮）

## フォルダ構成

```
youtube/
├─ README.md                 … このファイル（制作フロー）
├─ research/notes.md         … ジャンル選定・規約・競合のリサーチ結果
├─ episodes/
│   └─ 001_saizeriya/
│       ├─ episode.json      … 台本＋シーン定義（これ1つで動画が決まる）
│       ├─ description.md    … 概要欄のテンプレ（{{CHAPTERS}} は自動で埋まる）
│       └─ factcheck.md      … 数字と出典の確認表
├─ pipeline/
│   ├─ setup.sh              … 初回セットアップ（ライブラリ・フォント・アイコン・地図データ）
│   ├─ build.py              … episode.json → 動画・サムネ・字幕・概要欄（全体の進行役）
│   ├─ motion.py             … アニメーション描画（skia）。ショット種別ごとの演出
│   └─ audio.py              … ナレーション合成・BGM 自動生成・ミックス
└─ build/                    … 生成物（git 管理外）
```

## 1本あたりの流れ（目安 3〜4時間）

| # | 工程 | 担当 | 時間 | やること |
|---|---|---|---|---|
| 1 | ネタ選定 | AI→人 | 15分 | AI が候補を出す → 人が1つ選ぶ。「誰もが知っている」「数字で意外性が出る」企業を優先 |
| 2 | リサーチ | AI | 30分 | 決算短信・決算説明資料・主要報道から数字と事実を集め、`factcheck.md` を作る |
| 3 | 事実確認 | **人** | 30分 | `factcheck.md` の「要確認」を一次資料（会社 IR の PDF）で照合する |
| 4 | 台本 | AI→**人** | 45分 | AI が `episode.json` を書く → 人が**独自の結論・切り口を最低1つ足す** |
| 5 | ビルド | 自動 | 5分 | `python3 pipeline/build.py episodes/<id> --tts voicevox` |
| 6 | 試写 | **人** | 30分 | 通しで見る。誤読は該当行の `say` を直して再ビルド |
| 7 | 公開 | 人 | 15分 | 下の「公開チェックリスト」に沿ってアップロード |
| 8 | 振り返り | AI | 15分 | 公開1週間後、YouTube Studio の数字（維持率・CTR）を AI に渡して次回の改善点を出す |

週5〜15時間なら、**週1〜2本**のペースが現実的。

## コマンド

```bash
./pipeline/setup.sh                                          # 初回のみ
python3 pipeline/build.py episodes/001_saizeriya --only segments   # 1シーンだけ描画して確認
python3 pipeline/build.py episodes/001_saizeriya                   # 仮ナレーション（Open JTalk）で全編
python3 pipeline/build.py episodes/001_saizeriya --tts voicevox --speaker 13   # 本番用ナレーション
```

## episode.json の書き方

- `scenes[]` が1つの章。`chapter` がチャプターカード（「CHAPTER 01」）とチャプター欄になる。
- `lines[]` が1行ずつのナレーション兼字幕。読み間違えるものは
  `{"text": "表示する字幕", "say": "読ませる文"}` と書き分ける（例：`2.9%` → `2点9パーセント`）。
- `shots[]` で画面を切り替える。`{"from": 行番号, "visual": {...}}` の行から次のショットまでが1カット。
  1〜2行ごとに画面が変わるようにすると、「スライド感」がなくなる。
- 要素の `"at": 行番号` で、その行が読まれた瞬間に要素を出せる（ナレーションと演出の同期）。
- 文字列の `[ ]` で囲んだ部分はアクセント色になる。

| visual.type | 演出 |
|---|---|
| `title` / `headline` | 大見出し。文字が下から順に現れる。`icon`・`kicker`・`sub` 付き |
| `doria` | ドリアのイラスト（湯気が動く）＋値札のカウントアップ |
| `ring` | 円グラフが伸びて割合がカウントアップ |
| `year` | 年号がカウントアップする年表カット |
| `pricedrop` | 旧価格に取り消し線 → 新価格 |
| `stats` | 数字カードのカウントアップ |
| `bars` | 構成比の帯グラフが伸びる |
| `map` | アジア地図で国を塗り、拠点がパルス表示 |
| `flow` | アイコンの流れ図。線が伸び、中間業者に「+利益」が付く |
| `checklist` / `formula` / `linechart` / `timeline` / `bignum` | 箇条書き・式・折れ線・年表・大きな数字 |
| `image` | 用意した写真・AI生成画像をゆっくりズーム（ケン・バーンズ）して表示 |

全カットに共通で、ゆっくりしたカメラのズーム、カット間のクロスフェード、背景の光の揺らぎ、
フィルムグレイン、周辺減光、シネマ風の字幕がかかる。BGM（アンビエント）とチャプター切り替えの効果音も自動生成し、
ナレーション中は BGM を自動で下げる（ダッキング）。音量は YouTube 基準の -14 LUFS に揃える。

視聴維持の設計とテロップの使い分けは `research/retention.md` を参照。

### 写真・映像素材を足すとき

実写は `{"type": "footage", "path": "assets/footage/xxx.mp4", "fallback": {...}}` で入れる。
動画・写真のどちらでもよく、映画風の色調補正とゆっくりしたズームが自動でかかる。素材が無いあいだは `fallback` の演出が入る。
各回に必要な素材は `episodes/<id>/shotlist.md` にまとめる。

`assets/` に画像を置いて `{"type": "image", "path": "assets/xxx.jpg", "text": "見出し"}` で使える。
使ってよいのは **自分で撮った写真・商用利用可のストック素材（Pexels、Pixabay など）・自分で生成した AI 画像** だけ。
他人の YouTube 動画やテレビ映像、企業の公式写真・ロゴは使わない（著作権・商標の侵害になり、収益化も止まる）。

## 量産型（inauthentic content）と判定されないためのルール

YouTube は AI の利用そのものではなく、「テンプレートで量産された、動画ごとの違いが小さいコンテンツ」の収益化を止める。
そのため次を毎回守る。

- [ ] 数字は**会社の一次資料**から取り、図解はその回のためにオリジナルで作る（フリー素材の使い回しをしない）
- [ ] 各回に**その回だけの問い**と、**人が考えた結論**がある（台本をそのまま AI 任せにしない）
- [ ] シーン構成を毎回同じにしない（使う `visual.type` の順番や数を変える）
- [ ] 投稿は量より質。週1〜2本を上限にする
- [ ] ナビゲーター役を「投資の専門家」として扱わない。銘柄の売買を勧めない
- [ ] 公式資料で確認できない話は「と言われています」「と報じられています」と書く
- [ ] 根拠のない「闇」「ブラック」系の煽りをしない。企業ロゴ・公式画像を使わない

## 公開チェックリスト

- [ ] 動画の長さが **8分以上**（ミッドロール広告を入れられる）
- [ ] タイトル・サムネ・概要欄（`build/<id>/description.txt`）
- [ ] 字幕ファイル `captions.srt` をアップロード
- [ ] 「改変または合成されたコンテンツ」の設定を確認する（リアルな人物・出来事に見える合成映像を使った場合は「はい」）
- [ ] 合成音声のクレジットを概要欄に入れる（VOICEVOX はキャラクターごとの利用規約に従い「VOICEVOX:キャラクター名」を表記）
- [ ] 公開直前に、`factcheck.md` の「最新状況を確認」項目を見直す

## 本番化のためのアップグレード（優先度順）

1. **ナレーション**：VOICEVOX エンジン（`http://127.0.0.1:50021`）を使う。声は episode.json の `voice` で設定
   （`speaker` 話者ID、`speed` 速さ、`pitch` 高さ、`intonation` 抑揚、`pause` 読点の間）。
   行ごとに `"voice": {...}` で上書きでき、`？` で終わる行のあとは自動で間を長めにとる。
   エンジンの導入：GitHub の voicevox_engine リリース（linux-cpu-x64）を展開して `./run` を起動する。
   概要欄に「VOICEVOX:キャラクター名」のクレジットが必要。
2. **実写・イメージ素材**：ストック素材や AI 生成画像を `image` ショットで差し込む
3. **BGM**：自動生成の BGM を、YouTube オーディオライブラリの曲に差し替えるとさらに良くなる
