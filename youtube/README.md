# YouTube「儲けのカラクリ研究所」制作フロー

身近な企業の「儲けのカラクリ」を決算の数字で解き明かす、顔出し・声出しなしの解説チャンネル。
台本・図解・ナレーション・字幕・サムネイル・概要欄までを AI とスクリプトで生成し、
**人間は「切り口の決定」「事実確認」「試写」の3点だけ**を担当する。
（チャンネル名は仮）

## フォルダ構成

```
youtube/
├─ README.md                 … このファイル（制作フロー）
├─ research/notes.md         … ジャンル選定・規約・競合のリサーチ結果
├─ episodes/
│   └─ 001_saizeriya/
│       ├─ episode.json      … 台本＋シーン定義（これ1つで動画が決まる）
│       ├─ description.md    … 概要欄のテンプレ（{{CHAPTERS}} は自動で埋まる）
│       └─ factcheck.md      … 数字と出典の確認表
├─ pipeline/
│   ├─ setup.sh              … 初回セットアップ（ライブラリとフォントの取得）
│   └─ build.py              … episode.json → 動画・サムネ・字幕・概要欄
└─ build/                    … 生成物（git 管理外）
```

## 1本あたりの流れ（目安 3〜4時間）

| # | 工程 | 担当 | 時間 | やること |
|---|---|---|---|---|
| 1 | ネタ選定 | AI→人 | 15分 | AI が候補を出す → 人が1つ選ぶ。「誰もが知っている」「数字で意外性が出る」企業を優先 |
| 2 | リサーチ | AI | 30分 | 決算短信・決算説明資料・主要報道から数字と事実を集め、`factcheck.md` を作る |
| 3 | 事実確認 | **人** | 30分 | `factcheck.md` の「要確認」を一次資料（会社 IR の PDF）で照合する |
| 4 | 台本 | AI→**人** | 45分 | AI が `episode.json` を書く → 人が**独自の結論・切り口を最低1つ足す** |
| 5 | ビルド | 自動 | 5分 | `python3 pipeline/build.py episodes/<id> --tts voicevox` |
| 6 | 試写 | **人** | 30分 | 通しで見る。誤読は該当行の `say` を直して再ビルド |
| 7 | 公開 | 人 | 15分 | 下の「公開チェックリスト」に沿ってアップロード |
| 8 | 振り返り | AI | 15分 | 公開1週間後、YouTube Studio の数字（維持率・CTR）を AI に渡して次回の改善点を出す |

週5〜15時間なら、**週1〜2本**のペースが現実的。

## コマンド

```bash
./pipeline/setup.sh                                          # 初回のみ
python3 pipeline/build.py episodes/001_saizeriya --only segments   # 1シーンだけ描画して確認
python3 pipeline/build.py episodes/001_saizeriya                   # 仮ナレーション（Open JTalk）で全編
python3 pipeline/build.py episodes/001_saizeriya --tts voicevox --speaker 13   # 本番用ナレーション
```

## episode.json の書き方

- `scenes[]` が1つの画面。`visual.type` で見た目を選ぶ：
  `title` / `stats`（数字カード）/ `share_flip`（構成比の比較）/ `flow`（流れ図）/
  `bullets`（箇条書き）/ `formula`（式）/ `timeline`（年表）
- `lines[]` が1行ずつのナレーション兼字幕。読み間違えるものは
  `{"text": "表示する字幕", "say": "読ませる文"}` と書き分ける（例：`2.9%` → `2点9パーセント`）。
- `chapter` はそのままチャプターと概要欄に入る。

## 量産型（inauthentic content）と判定されないためのルール

YouTube は AI の利用そのものではなく、「テンプレートで量産された、動画ごとの違いが小さいコンテンツ」の収益化を止める。
そのため次を毎回守る。

- [ ] 数字は**会社の一次資料**から取り、図解はその回のためにオリジナルで作る（フリー素材の使い回しをしない）
- [ ] 各回に**その回だけの問い**と、**人が考えた結論**がある（台本をそのまま AI 任せにしない）
- [ ] シーン構成を毎回同じにしない（使う `visual.type` の順番や数を変える）
- [ ] 投稿は量より質。週1〜2本を上限にする
- [ ] ナビゲーター役を「投資の専門家」として扱わない。銘柄の売買を勧めない
- [ ] 公式資料で確認できない話は「と言われています」「と報じられています」と書く
- [ ] 根拠のない「闇」「ブラック」系の煽りをしない。企業ロゴ・公式画像を使わない

## 公開チェックリスト

- [ ] 動画の長さが **8分以上**（ミッドロール広告を入れられる）
- [ ] タイトル・サムネ・概要欄（`build/<id>/description.txt`）
- [ ] 字幕ファイル `captions.srt` をアップロード
- [ ] 「改変または合成されたコンテンツ」の設定を確認する（リアルな人物・出来事に見える合成映像を使った場合は「はい」）
- [ ] 合成音声のクレジットを概要欄に入れる（VOICEVOX はキャラクターごとの利用規約に従い「VOICEVOX:キャラクター名」を表記）
- [ ] 公開直前に、`factcheck.md` の「最新状況を確認」項目を見直す

## 本番化のためのアップグレード（優先度順）

1. **ナレーションを VOICEVOX に変更**（無料。自分の PC でエンジンを起動して `--tts voicevox`）。
   いまの Open JTalk は機械的なので、仮ナレーション専用。
2. **BGM**：YouTube オーディオライブラリから1曲選び、ffmpeg で小さく重ねる
3. **挿絵**：画像生成 AI で、各シーンにイメージイラストを1枚追加（実在の人物・ロゴは生成しない）
4. **動き**：数字のカウントアップや、グラフが伸びるアニメーション
